# **2. Meeting Retrieval Logic**

Based on detected input:

---

## **A. If user gives *Teams Meeting Join Link / Meeting ID***

Use Graph API to fetch:

1. **Call Record**
   `/communications/callRecords?$filter=joinWebUrl eq '{joinUrl}'`

2. Extract:

   * Transcript (if available)
   * Recording file link
   * Participant metadata
   * Duration

3. If transcript exists → skip transcription
   If only audio/video exists → transcribe it

---

## **B. If user gives a *Video Link*** (Any type)

### **Case 1 — OneDrive/SharePoint (Microsoft 365 Recording)**

* Unwrap SafeLink to get real URL
* Identify file using Graph:
  `/drive/items/{id}`
* Download using:
  `/drive/items/{id}/content`

### **Case 2 — Public Video URL**

* Download via HTTP request

### **Continue → transcription pipeline**

---

## **C. If user uploads *Video or Audio File***

* Accept file directly
* Move to transcription

---

## **D. If user uploads *Transcript File***

* Bypass transcription
* Directly process text into summary + action items

---

# **3. Transcription Pipeline**

For audio/video:

1. **Chunking**

   * Split long files (>5 min) into smaller 1–5 min segments

2. **Azure Speech-to-Text**

   * Language auto-detection
   * Speaker diarization (speaker separation)

3. **Transcript Normalization**

   * Merge chunks
   * Remove filler words
   * Attach speaker labels

4. Output:

   * Clean transcript
   * Timestamps
   * Speaker mappings

✅ 2. Database Schema (SQL)
TABLE 1 — projects

Holds all project-level metadata.

CREATE TABLE projects (
    project_id        SERIAL PRIMARY KEY,
    name              VARCHAR(255) NOT NULL UNIQUE,
    description       TEXT,
    created_at        TIMESTAMP DEFAULT NOW(),
    updated_at        TIMESTAMP DEFAULT NOW()
);

TABLE 2 — meetings

Stores metadata for each meeting (regardless of input type).

CREATE TABLE meetings (
    meeting_id        SERIAL PRIMARY KEY,
    project_id        INT REFERENCES projects(project_id),
    meeting_title     VARCHAR(255),
    meeting_date      TIMESTAMP,
    meeting_type      VARCHAR(50),     -- video link, file upload, teams join link etc.
    teams_meeting_id  VARCHAR(255),    -- optional
    join_url          TEXT,            -- optional Teams link
    transcript_text   TEXT,            -- processed transcript
    summary_text      TEXT,            -- LLM summary
    sharepoint_path   TEXT,            -- location of stored files
    created_at        TIMESTAMP DEFAULT NOW(),
    updated_at        TIMESTAMP DEFAULT NOW()
);

TABLE 3 — meeting_files

All files (recording, transcript file, summary file, etc.) related to a meeting.

CREATE TABLE meeting_files (
    file_id           SERIAL PRIMARY KEY,
    meeting_id        INT REFERENCES meetings(meeting_id),
    file_type         VARCHAR(50),    -- video, audio, transcript, summary, json, raw_text
    file_name         VARCHAR(255),
    file_path         TEXT,           -- local or SharePoint
    uploaded_at       TIMESTAMP DEFAULT NOW()
);

TABLE 4 — users (optional, if storing internal users)

Used for planner syncing + assignment.

CREATE TABLE users (
    user_id           SERIAL PRIMARY KEY,
    display_name      VARCHAR(255),
    email             VARCHAR(255) UNIQUE,
    teams_user_id     VARCHAR(255),   -- Microsoft Graph user ID
    created_at        TIMESTAMP DEFAULT NOW()
);

TABLE 5 — action_items

Main table generated from LLM summarization.

CREATE TABLE action_items (
    action_id         SERIAL PRIMARY KEY,
    meeting_id        INT REFERENCES meetings(meeting_id),
    project_id        INT REFERENCES projects(project_id),
    
    title             VARCHAR(500) NOT NULL,
    description       TEXT,
    owner_user_id     INT REFERENCES users(user_id),
    
    priority          VARCHAR(20),        -- High, Medium, Low
    status            VARCHAR(20) DEFAULT 'Not Started',
    
    due_date          TIMESTAMP,
    created_at        TIMESTAMP DEFAULT NOW(),
    updated_at        TIMESTAMP DEFAULT NOW()
);

TABLE 6 — planner_tasks (1-to-1 with action items)

Stores mapping to Microsoft Planner tasks created for each action item.

CREATE TABLE planner_tasks (
    planner_task_id       SERIAL PRIMARY KEY,
    action_id             INT UNIQUE REFERENCES action_items(action_id),

    planner_task_graph_id VARCHAR(255),    -- Graph API ID
    bucket_id             VARCHAR(255),    -- Planner bucket
    plan_id               VARCHAR(255),    -- Planner plan
    created_at            TIMESTAMP DEFAULT NOW(),
    updated_at            TIMESTAMP DEFAULT NOW()
);

TABLE 7 — reminders

Used for sending reminders 24 hours before due date.

CREATE TABLE reminders (
    reminder_id       SERIAL PRIMARY KEY,
    action_id         INT REFERENCES action_items(action_id),
    
    reminder_time     TIMESTAMP,           -- due_date - interval '24 hours'
    sent              BOOLEAN DEFAULT FALSE,
    sent_at           TIMESTAMP,
    
    created_at        TIMESTAMP DEFAULT NOW()
);
